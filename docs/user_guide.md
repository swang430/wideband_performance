# UniCon 现场调试与验证手册 (User Guide)

欢迎使用 **UniCon (Universal Control)** 调试控制台。本手册专为早期使用者（射频工程师、驱动开发人员、现场测试工程师）编写，旨在帮助您快速掌握如何通过 UniCon 验证底层仪表驱动和排查物理环境问题。

---

## 1. 快速启动 (Getting Started)

UniCon 提供了开箱即用的**独立桌面版应用程序**，无需在现场繁琐地配置 Python 环境或启动后台服务。

### 跨平台分发与安装指南

这套桌面软件的便携性极其强大，但您需要根据目标电脑的操作系统选择正确的启动方式：

*   🍎 **在 Mac（苹果系统）之间拷贝**：
    **直接 Copy！不需要 Clone 代码！**
    如果您想把本软件发给实验室的另一台 Mac，只需将编译好的 `UniCon_Desktop.app` 打成 `.zip` 压缩包（以防止 macOS 破坏执行权限），然后用 U盘 或微信发过去。在另一台 Mac 上解压后**双击即可运行**。目标电脑上**完全不需要安装 Python、Node.js 或是任何代码环境**。
    
*   🪟 **在 Windows 或 Linux 上运行**：
    **必须从 GitHub Clone 代码进行本地编译。**
    因为在 Mac 上打包出来的 `.app` 二进制文件无法在 Windows 上运行。如果目标机器是 Windows 系统，您需要：
    1. 在目标 Windows 电脑上从 GitHub clone 本项目的代码。
    2. 安装并激活 Python 虚拟环境 (`pip install -r requirements.txt`，详见代码库)。
    3. 在命令行执行 `pyinstaller desktop_app.py ...` (参考仓库中的打包脚本)。
    4. 系统会自动为您编译出一个纯正的 `UniCon_Desktop.exe`。之后，在 Windows 上只需拷这个 `.exe` 文件就能独立运行了。

## 2. 核心功能一：局域网探针与自动配置 (Instrument Probe)

当您到达一个陌生的测试现场，不清楚各个仪表的真实 IP 地址时，不要盲目盲猜。

1. 点击控制台左上角的 🔍 **Probe** 按钮。
2. 如果您知道某台仪器的 IP，可以在输入框填入（例如 `TCPIP0::192.168.1.100::INSTR`）；如果不填，系统将默认在局域网内广播嗅探。
3. 点击 **Run Probe**。系统会自动尝试连接并发送 `*IDN?` 指令。
4. **一键同步 (Sync to config.yaml)**：
   扫描结束后，表格会列出所有在线的设备及其身份（IDN）。
   如果发现新设备，点击右下角的 **Sync to config.yaml** 按钮。系统会根据设备的 IDN 智能判断角色（如看到 `CMW` 则归为 `integrated_tester`），并将这套真实的物理拓扑自动覆盖写入本地的 `config.yaml` 配置文件中。
   *之后您在左侧边栏看到的，就是真实物理世界的倒影。*

## 3. 核心功能二：仪表连接与纯 SCPI 透传 (Playground)

在配置好物理地址后，您可以进行底层的协议验证：

1. 点击 🔗 **Connect** 按钮（如果是研发阶段，可以点击 `Connect (Sim)` 开启纯软件模拟模式）。左侧面板的设备状态会变绿。
2. **选择仪表**：在左侧列表中点击您要操作的目标仪表（**注：选中后背景会变色突出显示**）。
3. **单步调试 (Single SCPI Execution)**：
   在中间的输入框中敲入标准的 SCPI 字符串，例如：
   *   `*IDN?` （查询身份）
   *   `SYSTem:ERRor?` （查询硬件报错）
   按下回车或点击 `Send`，下方会立刻显示仪表的原生返回值。
4. **批量互操作性测试 (Batch Interoperability Test)**：
   当您手里有一段从旧系统或原厂技术支持那里拷贝来的初始化脚本时，直接粘贴进下方的多行文本框。系统会自动逐条下发，并在表格中清晰地标注哪一条成功、哪一条超时失败。

---

## 4. 核心功能三：驱动 API 高阶验证 (Driver Verification)

这是为驱动开发者和现场排障量身定制的“大杀器”。在这里，您不需要懂任何生涩的 SCPI 语法，直接调用 Python 级别的高阶抽象。

1. 在左侧选中一台仪表（例如 `CMW500`）。
2. 在 **Driver API Verification** 模块的下拉菜单中，系统会通过反射自动列出这台仪表支持的所有高级方法（例如 `lte.configure_rf` 或 `wlan.start_signaling`）。
3. **输入参数**：在 Arguments 输入框中以严格的 **JSON 格式**填入该方法需要的参数。
   *例如：`{"band": "OB1", "dl_channel": 300, "tx_power_dbm": -40}`*
4. 点击 **Execute Method** 执行。
5. **深挖现场报错**：
   如果指令执行失败，不要惊慌。结果区域会弹出一个红色的折叠面板 **"View Debug Details"**。
   展开它，您将看到双重诊断报告：
   *   **Python Traceback**：告诉您代码层面哪里写错了（例如参数类型传错）。
   *   **Hardware System Errors (SYST:ERR?)**：系统会在失败后自动抽干仪表底层的硬件错误队列。如果这里显示 `-222, "Data out of range"`，说明您刚才设置的频率或功率超出了这台物理仪表的量程！拿着这个证据去修改驱动代码即可。
